# V1.6 架构优化 / Architecture optimization

**目标**: 在功能、性能、可靠性都不变的前提下, 减少生产代码量。代码越少, V2 的改造越快, 人和 AI 读改代码时也越不容易出错。

**起点**: 生产 Python 206 个文件, 488,311 token, 约 8.7 万行有效代码。计量口径见 [`tools/equivalence_gate/size.py`](../tools/equivalence_gate/size.py): 只数 Python token, 注释、空行、缩进都不算, 所以改格式不会让数字变小, 只有真正删掉代码才会。

**任务列表**: [milestone V1.6 架构优化](https://github.com/billion-token-one-task/Deepgraph/milestone/1)

> English summary: V1.6 shrinks the production code without changing what it
> does. Every pull request is judged by an automatic equivalence gate that
> records the base branch and the PR side by side and fails on anything the PR
> loses. Pick an issue from the milestone, comment to claim it, and follow the
> two-step flow below (lock behaviour with tests first, then reduce).

## 怎么参与

1. 在 milestone 里挑一个任务 issue, 评论"认领"。维护者把它分配给你。每人同时只领一个任务; 7 天没有进展, 任务会重新开放。
2. 标着 **先锁行为** 的任务分两个 PR:
   - **PR 1 锁行为**: 只加测试, 不改业务代码。目标是把这个模块现在的输入输出固定下来, 让下一步有测试兜底。
   - **PR 2 等价压缩**: PR 1 合并后再做。压缩后的代码必须通过 PR 1 的测试和等价闸。
   测试已经充分的模块可以直接做 PR 2。
3. PR 描述里写**等价论证**: 每一处删改为什么不改变行为。模板见下文。
4. 合并条件: CI 的等价闸全绿, 维护者在真实数据上复核通过, 代码审阅通过。

## 允许做什么

- 合并重复的函数和代码块。注意: 结构相同不等于语义相同, 合并前要核对常量和分支, 并把差异做成参数。
- 用明确的数据类型(例如 `dataclass` 或 `contracts/` 里已有的类型)在模块边界统一解析一次数据, 替换各处重复的 `.get(...) or {}`、`isinstance` 判断和 `try/except` 兜底。
- 删除只在逻辑上不可能触发的防御分支, 前提是在 PR 里写清楚为什么不可能触发。
- 拆分或合并函数, 换更直接的写法, 用标准库或项目已有的依赖替代手写实现。

## 不允许做什么

- 改提示词文本(发给 LLM 的字符串)。
- 改 SQL 语义、表结构、索引。
- 改接口路径、返回字段、状态码。
- 改判定阈值、默认配置、重试和超时参数。
- 改被其他程序读取的输出, 例如日志里的标记和报告格式。
- 删除或放宽已有测试(和被删代码一起删的测试除外, 需在 PR 里说明)。
- 新增依赖。确实需要时, 先在 issue 里讨论。
- 单个 PR 改动超过约 800 行。范围太大请拆开。

## 等价闸

每个指向 `master` 的 PR 都会自动运行 [等价闸](../.github/workflows/equivalence-gate.yml)。它在同一台机器上分别记录 base 分支和 PR 的行为, 任何一项比 base 少了都会失败:

| 检查 | 内容 |
|---|---|
| tests | base 上通过的每个测试, PR 上仍然通过 |
| imports | 每个生产模块都能单独导入 |
| routes | Web 路由表不少一条 |
| undefined names | 不新增未定义名字 (ruff F821) |
| entry scripts | systemd 和运维脚本启动的入口仍能编译 |
| outside symbols | 仓库外脚本用到的符号仍然存在 |
| schema | 建库后的列和索引完全一致 |
| PostgreSQL tests | `tests/integration` 在真实 PostgreSQL 上逐文件通过 |
| API responses | 在同样的合成数据上, 每个 GET 接口的返回完全一致 |

闸的代码始终取自 base 分支, PR 改不了评判自己的规则。CI 的 Summary 页同时给出代码量变化。

本地运行:

```bash
docker run -d --name dg-gate-pg -p 55432:5432 -e POSTGRES_USER=dgtest -e POSTGRES_HOST_AUTH_METHOD=trust pgvector/pgvector:pg16
pip install -r requirements.txt pytest==9.0.3 ruff==0.17.1
git worktree add ../base origin/master
python -I tools/equivalence_gate/gate.py ../base out/base --pg postgresql://dgtest@127.0.0.1:55432 --tag base
python -I tools/equivalence_gate/gate.py . out/head --pg postgresql://dgtest@127.0.0.1:55432 --tag head
python -I tools/equivalence_gate/compare.py out/base out/head
python -I tools/equivalence_gate/size.py ../base .
```

## PR 描述模板

```markdown
任务: #<issue>
类型: 锁行为 / 等价压缩

## 改了什么
- ...

## 为什么行为不变
- <每一处删改一条: 改之前做什么, 改之后做什么, 为什么一样>

## 验证
- 等价闸: PASS (CI 链接)
- 代码量: tokens <before> -> <after>
```

## 和 V2 的关系

V2 要把诚信链收成一小组不变量加插件接口(见 [路线图](ROADMAP.md))。V1.6 先把现有代码压实, 让 V2 的改造建立在更小、测试更全的代码上。V1.6 不改架构边界, 只做等价变换。
