## C. Frontier bootstrap authority

**Problem.** A ResourceGrant needs a portfolio decision, which needs a Frontier
packet, which needs an evaluator, which needed a ResourceGrant.

**Resolution.** `FrontierEvaluationAuthority` (`contracts/meta_harness.py`) is a
new, strictly smaller authority -- not a ResourceGrant and unable to become
one:

* exactly one active Agenda and one persisted research problem;
* hard token ceiling (<= 20,000), TTL ceiling (<= 120 minutes), idempotency key;
* one pinned provider / model / model family / prompt version;
* `frontier_assessment` and nothing else; `backend_allowlist == ("llm",)`;
  `max_gpu_hours == 0`;
* agenda budget reserved through the same `agenda_resource_ledger` as every
  other spend, with an append-only usage ledger per attempt;
* independence from the proposer route is enforced, and provenance on the
  produced packet comes from the authority, never from the model's own claim.

Fail-closed paths, each covered by a test: unavailable provider, missing scope,
expired authority, malformed output, missing linked evidence, usage above the
cap. Every failure settles the ledger and closes the authority; none falls back
to an unscoped call. A consumed authority replays its packet id instead of
spending again.

Modules: `meta_harness/frontier_authority.py`,
`meta_harness/frontier_bootstrap.py`, evidence briefing in
`meta_harness/frontier_source.py`, operator routes in
`web/meta_harness_routes.py`
(`POST /frontier/authority`, `POST /frontier/bootstrap`,
`GET /frontier/authority/<id>/audit`).

**Open decision for the operator.** The independent evaluator is currently a
*model* on a route pinned to be independent of the proposer. If human
independent review is required instead, the smallest change is to keep the
authority as-is and require a reviewer signature on the produced packet before
`save_decision` accepts it (`meta_harness/reviewer_approval.py` already
provides the signature primitive). Say which you want; the safest available
option is implemented and documented meanwhile.

## D. Compute backend truth

**Verified.** No local GPU. Configuration carries a legacy
`DEEPGRAPH_GPU_BACKEND=colab` field alongside current `cpu,ssh_gpu`,
`DEEPGRAPH_GPU_MODE=ssh` and SSH reference fields; the Colab account manifest is
absent. Neither SSH GPU nor Colab is proven usable.

`meta_harness/backend_capability.py` states this explicitly:

| Backend | State | Why |
| --- | --- | --- |
| `cpu` | enabled | listed and locally verifiable |
| `ssh_gpu` | **unknown** | configured but never verified by a canary |
| `colab_gpu` | disabled | account manifest absent; CLI binary not configured |
| `local_gpu` | disabled | no GPU on the host |

A backend becomes `enabled` only when an operator records it in
`DEEPGRAPH_COMPUTE_VERIFIED_BACKENDS` after a real canary. `build_scheduler()`
builds only `enabled` backends and `submit_experiment_run` refuses anything
else, so an unknown backend can never receive ordinary work and nothing falls
back to another backend. A legacy field never enables anything on its own; it is
reported as a conflict. Only reference *names* are ever printed --
`scripts/meta_harness_backend_audit.py` is read-only and no-cost.

GPU grant enforcement (`tests/test_gpu_grant_enforcement.py`, 12 tests):
aggregate token and GPU-hour caps, max concurrency, **8-hour per-grant ceiling
that now applies even when an Agenda declares no policy**, backend allowlist
subset, short TTL (24h with GPU, 72h without) with expiry rejection, required
artifacts, reservation accounting, and promote/revisit-only issuance.
